## Story

**As a** ISKR (prestador do serviço),
**I want** o projeto Astro montado e publicável, com headers e cache corretos desde o primeiro deploy,
**so that** todo o trabalho seguinte caia no ambiente certo sem retrabalho de configuração.

## Acceptance Criteria

1. Projeto Astro criado com saída estática (`output: 'static'`), Node 20+ e npm, seguindo a estrutura de `docs/architecture.md` §4.
2. `npm run build` completa sem erro e gera `dist/` com HTML pronto (conteúdo visível no HTML, não montado por JS).
3. Uma página canário responde em `/`, com `lang="pt-BR"`, `charset=utf-8` e `viewport` corretos.
4. `vercel.json` aplica `X-Content-Type-Options`, `Referrer-Policy` e `Strict-Transport-Security` em **todas as rotas** (`source: "/(.*)"`).
5. `vercel.json` aplica `Cache-Control: public, max-age=31536000, immutable` em `/_astro/(.*)` e `/fonts/(.*)`.
6. `docs/requisitos-tecnicos-fixos.md` existe com o Apêndice A do PRD colado por inteiro (NFR14).
7. `README.md` explica como instalar, rodar em dev, buildar e publicar.
8. Zero JavaScript no bundle final: `dist/` não contém arquivo `.js` de runtime (NFR2).
   8a. `.gitignore` cobre pelo menos `node_modules/`, `dist/`, `.astro/`, `.vercel/` e `.env*`.
   8b. `scripts/check-links.mjs` implementado conforme `docs/architecture.md` §7.3, falhando quando encontrar: âncora interna inexistente; link externo que não esteja em `src/data/contatos.ts`; caractere fora do ASCII imprimível na querystring de um `wa.me`; imagem informativa sem `alt`.
   8c. `npm test` roda build + `check-links` + validação de HTML, e passa no projeto canário.
9. **(@devops)** Repositório criado no GitHub `iskarockets` — nunca na conta pessoal `lucas.nogueira` (NFR11).
10. **(@devops)** Projeto vinculado à conta Vercel **do cliente**, com preview respondendo e `curl -I` confirmando os headers do AC4 na raiz e numa rota inexistente.
11. O domínio `cuidahomecare.com` **não** foi alterado nesta story.

## Dev Notes

**Contexto:** greenfield. O repositório ainda não existe; esta story cria tudo do zero. O projeto substitui `https://cuidahomecare.com/`, hoje um export do Canva com ~3,4 MB de JS e nota 56 de performance.

**Stack decidida** (`docs/architecture.md` ADR-001): **Astro 5.x**, saída estática, **zero JS no cliente**, CSS nativo com custom properties, sem framework de CSS, sem React. O preset `nextjs-react` do AIOS **não se aplica** a este projeto.

**`astro.config.mjs` esperado:**

```js
import { defineConfig } from "astro/config";

export default defineConfig({
  output: "static",
  site: "https://cuidahomecare.com",
  build: { inlineStylesheets: "always" },
});
```

**`vercel.json`** — copiar de `docs/architecture.md` §6. Pontos que costumam sair errado:

- O `source` dos headers de segurança é `"/(.*)"`, não `"/"`. A NFR9 exige cobertura de todas as rotas, inclusive a 404.
- O HTML **não** leva `immutable`; só `/_astro/*` e `/fonts/*`.
- A diretiva `preload` no HSTS ficou pendente de decisão do Lucas (`docs/architecture.md` §10). **Incluir sem `preload`** até haver decisão.

**Redirecionamento `www` → apex** é configurado em Domains, na Vercel, e não no `vercel.json`.

**Orçamento de performance** (`docs/architecture.md` §7.1): 0 KB de JS, 15 KB de CSS, 60 KB de HTML. O AC8 é a primeira verificação disso.

**Regra de projeto aprovada pelo Lucas em 17/09:** fidelidade ao desktop cede quando o motivo é acessibilidade ou performance; mudança por gosto continua proibida.
